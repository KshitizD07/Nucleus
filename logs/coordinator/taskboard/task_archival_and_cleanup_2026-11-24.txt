3. WHY BEHIND THE CHANGE
   - In long-running development sessions with dozens of completed tasks, accumulating completed tasks in `.nucleus/tasks.json` inflates file sizes, consumes unnecessary context tokens for LLMs, and increases disk synchronization overhead.
   - Storing completed tasks in `.nucleus/tasks_archive.json` keeps the active board minimal while maintaining a full audit log.

4. WHY NOT THE ALTERNATIVE(S)
   - Permanently deleting completed tasks: Loses historical context, blame trail, and review notes.
   - Keeping tasks in one huge file with an "archived" boolean filter: Still forces agents to ingest and parse large JSON files on every task claim. Moving them to a separate file ensures zero token overhead.
