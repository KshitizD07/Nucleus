SESSION LOG: HARD LANE MISMATCH VALIDATION FOR TASK CLAIMS
================================================================================
Date       : 2026-11-24
Domain     : coordinator
Feature    : taskboard
Status     : Completed
--------------------------------------------------------------------------------

1. OBJECTIVE
   - Implement hard server-side and CLI-side lane validation when claiming tasks.
   - Prevent coding agents operating in one lane (e.g., frontend) from claiming tasks designated for another lane (e.g., backend), closing the architectural gap.

2. WORK PERFORMED & ARCHITECTURE DETAILS
   - Updated `TaskBoardManager.claimTask(taskId, nodeId, branch?, lane?)` in `@nucleus/coordinator` to validate that if `lane` is provided, `task.lane === lane`.
   - On mismatch, return `success: false` with explicit descriptive reason `Forbidden: Lane mismatch. Node '<nodeId>' in lane '<lane>' cannot claim task '<taskId>' belonging to lane '<task.lane>'`.
   - Updated `CoordinatorServer.handleTaskClaim` to look up the node's registered lane from `NodeRegistry` and pass it to `this.taskBoard.claimTask`. If the claim fails, dispatch `task:claim_failed` WebSocket envelope to the requesting node.
   - Updated `claimTaskLocally(workspaceRoot, taskId, assignedTo, lane?)` in `@nucleus/cli` and `packages/cli/bin/nucleus.js` to reject cross-lane claims locally.
   - Added unit test in `packages/cli/src/cli.test.ts` and integration test in `packages/coordinator/src/server/critique.integration.test.ts`.

3. WHY BEHIND THE CHANGE
   - While context files (`.nucleus/PEERS.md`) and WorkspaceJail confine file writes, autonomous agents without strict server-side validation could theoretically execute `nucleus claim <task-id>` or dispatch `task:claim` for tasks outside their lane, polluting task states and locking out the intended lane's agent.
   - Enforcing lane boundary checks at the coordinator mutex / taskboard layer guarantees deterministic ownership.

4. WHY NOT THE ALTERNATIVE(S)
   - Prompt-only enforcement: Relying solely on LLM compliance in system prompts or PEERS.md instructions is non-deterministic, especially for smaller or lightweight models.
   - Workspace-path heuristics only: Inferring lane solely from file paths doesn't prevent task claiming before any file edits begin. Server-level schema/state checks are deterministic and instant.
